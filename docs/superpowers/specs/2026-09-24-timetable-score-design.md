# 시간표·점수 설계

작성일: 2026-09-24
서브프로젝트: 5 / 7 (구간, 마감, 점수, 완주 판정)

## 배경

1~4번이 끝나 `main` 에 병합돼 있다. 버스가 노선을 달리고, 정류장에서 승객이
타고 내리고, 교차로에서 신호가 돌며 적색 통과가 위반으로 세어진다. 경찰차에
적발되면 주행이 끝난다.

아직 게임에 끝이 없다. 종점에 도착해도 아무 일도 없고, 시간이 흘러도 압박이
없다. 이 게임의 핵심 저울질 — "신호를 어겨 시간을 벌 것인가" — 은 시간 제한이
있어야 성립한다. 이 문서는 마감, 점수, 완주 판정을 다룬다.

전체 분해에서 이 문서의 자리:

1. OSM 베이크 파이프라인 — 완료
2. 버스 물리 + 입력 — 완료
3. 정류장·승객 시스템 — 완료
4. 신호·위반 시스템 — 완료
5. **시간표·점수·종착 판정** ← 이 문서
6. 교통 AI / 단속
7. 노선 선택 메뉴, 3개 노선 굽기, 배포

## 목표와 비목표

**목표**

- 노선을 정류장 10곳 단위 구간으로 잘라 한 판을 10분 안팎으로 만든다.
- 구간마다 마감을 노선 기하와 승객·신호 규칙에서 자동으로 계산한다.
- 남은 시간을 화면에 보여 주고, 끝 정류장 승하차가 끝나면 완주로 판정한다.
- 완주하면 항목별 점수, 총점, 별 등급을 결과 화면에 보여 준다.
- 결과 화면에서 다음 구간, 다시 하기, 메뉴로 갈 수 있다.

**비목표**

- 정류장별 시간표(정시성). 마감 하나로 저울질이 가장 선명하다. 나중에 점수
  항목으로 얹을 수 있다.
- 최고 점수 저장. 7번 서브프로젝트다.
- 메뉴 꾸미기. 7번이다. 여기서는 구간을 고를 수만 있으면 된다.
- 구간 사이 승객 이어받기. 구간은 빈 버스로 시작한다.
- 베이크 파이프라인 변경. 필요한 값이 전부 JSON 에 있다.

## 결정 요약

- **마감 하나.** 구간 전체에 제한 시간 하나를 둔다.
- **넘겨도 계속 달린다.** 초과한 초만큼 감점하고 완주는 인정한다. 실패로 끝나는
  길은 이미 경찰 적발이 있다.
- **마감은 자동 계산.** 기준 속도 상수 하나로 난이도를 조절한다.
- **구간 단위.** 간선 노선 하나가 한 판 약 1시간이라 정류장 10곳씩 자른다.
- **런타임에 자른다.** `RouteData.slice()` 가 잘린 `RouteData` 를 내고, 주행 씬의
  나머지는 그 데이터만 본다. 숫자를 바꿔도 다시 구울 필요가 없다.

## 구간

### 경계

`RouteData.sections() -> Array[Vector2i]` 가 구간마다 (첫 정류장, 끝 정류장)
인덱스를 낸다.

- 정류장을 `SECTION_STOPS = 10` 간격으로 자른다. **경계 정류장은 양쪽 구간이
  함께 쓴다.** 구간 1 = 0~10, 구간 2 = 10~20 …. 한 구간의 끝 정류장이 다음
  구간의 첫 정류장이라, 이어서 달리면 실제 노선처럼 끊김 없이 이어진다.
- 마지막 조각이 정류장 `SECTION_MIN_STOPS = 5` 곳보다 적으면 앞 구간에 붙인다.
- 정류장이 `SECTION_MIN_STOPS` 보다 적은 노선은 구간 하나다.

실데이터 기준으로 100번(61곳)은 6개, 654번(78곳)은 8개, 서대문03(19곳)은 2개다.

### 자르기

`RouteData.slice(section: int) -> RouteData` 는 새 객체를 돌려준다. 원본은 건드리지
않는다.

- **경로 선:** 첫 정류장 `progress_m` 에서 `LEAD_IN_M = 60` m 앞(0 미만이면 0)부터
  끝 정류장 `progress_m` 까지. 잘린 끝점은 `point_at_progress` 로 보간한다.
  출발하자마자 첫 정류장 반경에 들어가지 않게 여유를 둔다.
- **정류장:** 구간의 정류장만. `progress_m` 에서 잘린 시작 거리를 뺀다.
  `stop_targets` 는 새 경로 선에서 다시 만든다.
- **신호:** 잘린 경로 선에서 `SECTION_SIGNAL_M = 30` m 안에 있는 것만.
- **청크:** 노선 전체를 그대로 둔다. 도시는 `route_id` 로 청크를 올리고 성능 여유가
  크다(seoul-100 전체 119 fps).
- `id`, `display_name`, `from_name`, `to_name` 은 원본을 따르되 `section` 필드에
  구간 번호를 담는다.

`PassengerPlan` 은 받은 정류장 수만 보므로, 목적지는 자동으로 구간 안에서만 뽑히고
끝 정류장에서 전원이 내린다(기존 종점 로직). 순찰 경찰차도 잘린 경로를 왕복한다.

## 마감

`Timetable` (`scripts/timetable.gd`, RefCounted, static 함수만)

```
주행 = 경로 길이 ÷ BASE_SPEED_MPS            (30 km/h = 8.33 m/s)
정차 = 정류장 수 × expected_dwell()
신호 = 신호 수 × SIGNAL_WAIT_S                (8.25 s)
마감 = 올림(주행 + 정차 + 신호, 10 s 단위)
```

- `expected_dwell()` 은 `PassengerPlan` 의 대기 인원 분포(`maxi(0, randi_range(-3, 8))`)
  를 열거해 `dwell_for(n, 0, WALK_GUESS_M, n)` 의 기댓값을 낸다. 0 명이면 서지
  않으므로 0 이다. `WALK_GUESS_M = 3` m. 하차는 탑승과 동시에 진행되고(`maxf`)
  대부분 탑승 시간에 묻히므로 뺀다. 값은 약 10 초다.
  대기 인원 분포를 `PassengerPlan` 의 상수로 옮겨 두 곳이 같은 수를 보게 한다.
- `SIGNAL_WAIT_S` 는 적색일 확률 1/2 × 평균 대기 `(GREEN_S + YELLOW_S) / 2` 이다.
  `TrafficSignal` 상수에서 계산한다.
- 예상 마감은 구간 약 3~4 km 기준 8~12분이다.

## 시계와 완주

`RunClock` (`scripts/run_clock.gd`, Node)

```gdscript
signal finished

var deadline_s := 0.0
var elapsed_s := 0.0
var boarded_total := 0     # 구간에서 태운 승객 누적
var respawns := 0
var is_running := true
var is_finished := false
```

- 첫 `_physics_process` 부터 `elapsed_s` 를 올린다. 승하차 시간도 들어간다.
- `BoardingWatch.boarding_finished` 를 듣는다. 탑승 인원을 `boarded_total` 에 더하고,
  방금 끝난 정차가 끝 정류장이면 시계를 멈추고 `finished` 를 낸다.
- `ViolationWatch.busted` 를 들으면 시계를 멈춘다. `is_finished` 는 켜지 않는다.
- `respawns` 는 `drive.respawn()` 이 실제로 되돌렸을 때만 올린다(승하차 중 막힌
  리스폰은 세지 않는다).
- 완주 뒤에는 `drive.gd` 가 경찰 적발 때처럼 브레이크만 건다.

## 점수

`ScoreCard` (`scripts/score_card.gd`, RefCounted)

입력은 숫자뿐이다 — 걸린 시간, 마감, 태운 승객, 위반, 카메라 위반, 놓친 정류장,
못 태운 승객, 리스폰. 출력은 항목 목록 `[{"label", "count", "points"}]`, 총점, 별.

| 항목 | 점수 |
|---|---|
| 완주 | +1000 |
| 태운 승객 1명 | +20 |
| 마감보다 일찍 (1초당) | +2 |
| 마감 초과 (1초당) | −5 |
| 신호 위반 (카메라 없음) | −50 |
| 카메라 단속 | −150 |
| 놓친 정류장 | −100 |
| 못 태운 승객 1명 | −10 |
| 리스폰 1회 | −30 |

- 위반 수 `violations` 는 카메라 위반을 포함한다. 카메라 없는 위반은
  `violations - camera_violations` 다.
- 초는 내림한 정수로 계산한다.
- **별:** 마감 안 + 감점 합계(시간 항목 제외) 150 이하면 3, 마감 안이면 2, 완주면 1.
- 경찰 적발은 `ScoreCard` 를 쓰지 않는다. 결과 화면이 "적발"만 띄운다.
- 점수표 상수는 모두 파일 맨 위에 둔다. 조정은 숫자만 바꾸면 된다.

저울질 근거: 카메라 없는 위반 한 번(−50)은 25초를 번 것(+2 × 25)과 같다. 적색 대기는
평균 16.5초, 최대 36초라 해볼 만한 도박이다. 카메라 교차로(−150)는 대부분 손해다.

## 화면

**`ClockHud`** (`scripts/clock_hud.gd`, CanvasLayer) — 화면 **오른쪽 위**.
`남은 시간 7:42`. 마감을 넘기면 빨간 `초과 +0:35`. 위반 HUD 가 왼쪽 위, 승하차
HUD 가 가운데 위라 겹치지 않는다.

**`ResultPanel`** (`scripts/result_panel.gd`, CanvasLayer) — 완주하거나 적발되면
뜬다. 반투명 판에:

- 완주: 구간 이름(`100번 · 구간 2/6`), 항목별 점수, 총점, 별(`★★☆`)
- 적발: `경찰에 적발됐습니다`
- 버튼: **다음 구간**(완주했고 마지막 구간이 아닐 때만), **다시 하기**, **메뉴**.
  키보드는 `Enter` 다음 구간, `R` 다시 하기.

기존 적발 때의 `R` 다시 시작은 결과 화면의 다시 하기와 같은 동작이라 그대로 둔다.

## 메뉴와 씬 배선

**메뉴** (`scripts/menu.gd`) — 노선 버튼을 누르면 같은 화면에 구간 버튼 목록을
펼친다. `구간 2 · 신대방삼거리 → 보라매공원 · 마감 10:40`. 구간을 고르면
`RouteData.selected_section` 에 담고 주행 씬으로 간다. `selected_id` 와 같은 static
변수다.

**주행 씬** (`scripts/drive.gd`)

- 노선을 읽은 직후 `data = data.slice(section_from_args())`. 이후 모든 코드는 잘린
  데이터만 본다. `city.load_city(route_id)` 는 원본 id 를 쓴다.
- `section_from_args()` 는 `--section=<n>` 이 있으면 그것, 없으면
  `RouteData.selected_section`. 범위를 벗어나면 0 이다.
- `RunClock`, `ClockHud`, `ResultPanel` 을 붙이고 신호를 잇는다.
- 다음 구간: `selected_section += 1` 후 `reload_current_scene()`.
- 메뉴: `change_scene_to_file("res://scenes/menu.tscn")`.

## 실패와 경계

- **정류장이 없는 노선**(구 산출물): `sections()` 는 빈 배열, `slice()` 는 원본을
  그대로 돌려주고, `RunClock` 은 끝을 판정하지 않는다. 시계만 돈다.
- **정류장 1곳짜리 구간**은 생기지 않는다(`SECTION_MIN_STOPS`).
- **리스폰으로 구간 밖**에 가는 일은 없다. 리스폰은 잘린 경로에서 가장 가까운 점을
  찾는다.
- **끝 정류장을 놓치면** 되돌아가 다시 서야 완주다. 기존 놓침 규칙과 같다.

## 결정 기록

- **구간 경계 정류장을 공유한다.** 겹치지 않게 자르면 구간 사이 한 정거장 구간이
  어디에도 속하지 않는다.
- **구간은 빈 버스로 시작한다.** 이어받으려면 구간 사이에 상태를 날라야 한다.
  한 구간이 10분이라 차이가 크지 않다.
- **청크는 자르지 않는다.** 성능 여유가 커서 로딩을 바꿀 이유가 없다.
- **마감에 승하차 시간을 넣는다.** 승하차 시간은 매 판 달라지는 변수이고, 그 편차가
  "이번 판은 빠듯한가"를 만든다.
