# 정류장·승객 설계

작성일: 2026-09-24
서브프로젝트: 3 / 7 (정차 판정, 승하차 시간, 대기 승객)

## 배경

1번(OSM 베이크), 2번(버스 물리·입력), 4번(신호·위반)이 끝나 `main` 에 병합돼
있다. 서울 3개 노선이 구워져 있고, 사람이 버스를 몰아 노선을 달리며, 교차로에는
신호가 돌고 적색 통과는 위반으로 세어진다.

지금은 정류장이 데이터로만 있다. 노선을 끝까지 달려도 아무 일이 없다. 이 게임의
핵심 루프인 "정류장마다 승객을 태우고 정해진 시간 안에 종점 도착"에서 앞의
절반이 비어 있는 셈이다. 이 문서는 정류장에 승객을 세우고, 정차를 판정하고,
승하차에 시간을 소모시키는 일을 다룬다.

전체 분해에서 이 문서의 자리:

1. OSM 베이크 파이프라인 — 완료
2. 버스 물리 + 입력 — 완료
3. **정류장·승객 시스템** ← 이 문서
4. 신호·위반 시스템 — 완료
5. 시간표·점수·종착 판정
6. 교통 AI / 단속
7. 노선 선택 메뉴, 3개 노선 굽기, 배포

이 문서가 만드는 승하차 소요시간은 5번(시간표)이 시간 제한을 정하는 근거가 된다.
신호 대기와 승하차가 소요시간을 흔들고, 그 편차가 "이번 판은 빠듯한가"를 매번
새로 재게 만드는 것이 목표다.

## 목표와 비목표

**목표**

- 정류장마다 대기 승객을 세우고, 멀리서도 인원이 보이게 한다.
- 정류장 앞에 정차하면 승하차가 진행되고 시간이 소모된다.
- 승하차 시간이 매번 달라진다 — 대기 인원, 하차 인원, 정차 위치 정확도로.
- 승객마다 목적지가 있어 탑승 인원이 노선 내내 오르내린다.
- 현재 탑승 인원과 다음 정류장을 화면에 표시하고, 5번 서브프로젝트가 읽어갈
  인터페이스를 낸다.

**비목표**

- 시간 제한, 점수, 완주 판정 — 5번 서브프로젝트다.
- 승객이 실제로 걸어와서 버스에 올라타는 연출. 캡슐이 사라지는 것으로 족하다.
- 하차 승객 메쉬. 내린 사람은 표현하지 않는다.
- 대기 인원이 시간이 지나며 늘어나는 것. 주행 시작 때 한 번 정하고 끝이다.
- 베이크 파이프라인 변경. `stops` 에 필요한 값이 이미 다 있다.

## 데이터

베이크는 건드리지 않는다. `assets/routes/route_<id>.json` 의 `stops` 가 이미
필요한 것을 담고 있다.

```json
{"name": "롯데마트", "x": 4559.41, "z": -7164.3,
 "progress_m": 44.0, "osm_node": 12152864460}
```

seoul-100 기준 정류장 114개, 총 길이 24,116 m, 정류장 간격 중앙값 154 m
(최소 21 m, 최대 1,104 m).

### 정차 목표점은 노드가 아니라 노선 위의 점이다

OSM `bus_stop` 노드는 도로 옆 인도에 찍혀 있다. seoul-100 의 정류장 114개를
노선 중심선까지 재면 중앙값 6.9 m, 90 백분위 16.6 m, 최대 28.6 m 다.

승객이 걸어오는 시간을 **노드까지의 거리**로 재면 차선에 완벽히 세워도 매번
페널티가 붙고, 28 m 떨어진 정류장은 피할 방법이 없는 24초를 물린다.

따라서 **정차 목표점은 노선 폴리라인 위의 `progress_m` 지점**이다. 걸어오는
시간은 버스가 멈춘 곳에서 이 목표점까지의 거리로 잰다. 표지판과 대기 승객
캡슐은 실제 노드 좌표(`x`, `z`)에 세운다 — 보이는 것은 인도 위에 있어야 한다.

## 승객 모델

`PassengerPlan` (RefCounted). 노드가 아니다 — 순수 로직이라 트리 없이 테스트한다.

**주행 시작 때:** 정류장마다 대기 인원을 뽑는다. `maxi(0, randi_range(-3, 8))` —
0~8명 범위에 0명이 1/3 로 흔하고 평균 2.9명이다. 균등 분포로 뽑으면 정류장
114곳 중 101곳에 사람이 있어 계속 서게 된다. 매 플레이 새로 뽑는다(시드 고정
안 함).

**탑승할 때:** 승객 한 명마다 목적지를 뽑는다 — 현재 정류장보다 **뒤쪽에 남은
정류장 중 균등 랜덤**. 목적지별 인원만 세므로 승객 객체는 만들지 않는다.

**정원 60명.** 입석 포함 서울 저상버스 기준이다. 초과분은 타지 못하고 정류장에
남는다. 남은 사람은 다시 오지 않는다 — 놓친 것으로 기록만 하고, 감점 여부는
5번이 정한다.

**종점:** 마지막 정류장에서 남은 전원이 하차한다.

### 승하차 시간

```
dwell = DOOR_S + walk_s + maxf(board_n * BOARD_S, alight_n * ALIGHT_S)
walk_s = (버스 정지 위치에서 정차 목표점까지 거리) / WALK_SPEED_MPS
```

- `DOOR_S = 3.0` — 문 개폐. 승객이 0명이어도 정차했으면 든다
- `BOARD_S = 1.2` — 1인 탑승. 교통카드 찍는 시간
- `ALIGHT_S = 0.8` — 1인 하차
- `WALK_SPEED_MPS = 1.2`
- 탑승과 하차는 **동시** 진행이다(앞문 승차, 뒷문 하차). 그래서 합이 아니라
  `maxf` 다
- 대기 인원이 0명이면 `walk_s` 도 0 이다. 걸어올 사람이 없다

seoul-100 대략치: 승객이 있는 정류장 약 76곳, 정차 한 번에 평균 7~10초(걸어오는
시간 포함)로 총 9~13분. 24 km 를 평균 25 km/h 로 달리면 58분이므로, 승하차가
전체의 15~20% 를 차지한다.

## 컴포넌트

4번 서브프로젝트와 같은 분리를 따른다 — 판정, 표현, HUD 가 각각 다른 파일이다.

### `PassengerPlan` (`scripts/passenger_plan.gd`, RefCounted)

대기 인원 생성, 목적지 배정, 정원 처리, dwell 계산. 위의 승객 모델이 전부 여기
있다. Node 가 아니므로 테스트가 `new()` 하고 바로 호출한다.

### `StopField` (`scripts/stop_field.gd`, Node3D)

정류장 표지판(기둥 + 판)과 대기 인원만큼의 캡슐을 세운다. `SignalField` 와 같은
격자 + 거리 컬링 패턴으로 버스 200 m 안만 갱신한다. 승객이 타면 해당 캡슐을
숨긴다. 충돌면은 붙이지 않는다 — 버스가 승객을 들이받아 주행이 막히는 쪽이 더
나쁘다.

머티리얼은 공유한다. seoul-100 은 정류장 114개에 대기 승객 최대 900여 명이라
개별 머티리얼을 만들면 안 된다.

### `BoardingWatch` (`scripts/boarding_watch.gd`, Node)

정차 판정과 승하차 타이머. `PassengerPlan` 을 들고 있다.

**정차 시작 조건** — 세 가지가 모두 참일 때:
- 버스가 어느 정류장의 정차 목표점 `STOP_RADIUS_M = 15.0` 안에 있다
- 버스 속도가 `STOP_SPEED_MPS = 0.5` 미만이다
- 그 정류장을 아직 처리하지 않았다

정류장 간격이 최소 21 m 라 반경이 겹친다. 겹치면 **가장 가까운 미처리 정류장
하나만** 잡는다.

**승하차 중:** 문이 열려 있으므로 버스는 움직이지 못한다. `drive.gd` 가 적발
처리와 같은 방식으로 브레이크만 건다(`apply_axes(0.0, 0.0, 1.0, false, delta)`).
타이머가 끝나면 문을 닫고 조작이 돌아온다.

**놓침:** 반경 안에 들어왔다 나갔는데 서지 않았으면 놓친 정류장이다. 되돌아가서
다시 반경 안에 정지하면 그때 승하차가 진행된다 — 돌아가는 데 드는 시간이 이미
충분한 벌이다.

**인터페이스** (5번 서브프로젝트가 읽는다):

```gdscript
signal boarding_started(stop_index: int)
signal boarding_finished(boarded: int, alighted: int)
signal stop_missed(stop_index: int)

var onboard := 0          # 현재 탑승 인원
var served := 0           # 승하차를 마친 정류장 수
var missed := 0           # 놓친 정류장 수
var left_behind := 0      # 정원 초과로 못 태운 사람 수
var is_boarding := false
var boarding_left := 0.0  # 남은 승하차 시간 (진행 바용)
```

### `BoardingHud` (`scripts/boarding_hud.gd`, CanvasLayer)

화면 **상단 중앙**. 위반 HUD 가 좌상단, 터치 컨트롤이 아래와 양옆을 쓰므로 겹치지
않는다.

- 다음 정류장 이름과 남은 거리
- 현재 탑승 인원 (`탑승 23명`)
- 승하차 중에는 진행 바와 `승하차 중 (타는 사람 5, 내리는 사람 2)`

### `drive.gd` 배선

`StopField`, `BoardingWatch`, `BoardingHud` 를 만들어 붙이고 신호를 연결한다.
`_physics_process` 의 적발 게이트 다음에 승하차 게이트를 넣는다 — 적발이 우선이다
(적발되면 주행 자체가 끝난다).

## 실패와 경계

- **구 버전 산출물에 `stops` 가 없거나 비어 있으면** 모든 컴포넌트가 조용히 아무
  것도 하지 않는다. 신호 쪽과 같은 규칙이다.
- **정류장이 1개뿐이면** 목적지를 뽑을 뒤쪽 정류장이 없다. 그 정류장은 종점으로
  취급해 전원 하차만 한다.
- **정차 목표점을 노선에서 못 찾으면**(`progress_m` 이 노선 길이를 넘으면) 마지막
  경로점으로 자른다.
- **승하차 중 리스폰**(`R`)은 막는다. 리스폰으로 승하차 시간을 건너뛸 수 있으면
  안 된다.

## 테스트

기존 헤드리스 러너(`tests/game/run_game_tests.sh`)에 두 씬을 더한다.

**`test_passenger_plan`** — `PassengerPlan` 순수 로직:
- 대기 인원이 0~8 범위 안이고, 많이 뽑으면 0명이 1/3 안팎으로 나온다
- 목적지가 항상 현재 정류장보다 뒤쪽이다
- 정원 60명 상한에서 초과분이 정류장에 남고 `left_behind` 로 세어진다
- 마지막 정류장에서 남은 전원이 하차한다
- dwell 공식: 승객 0명이면 `DOOR_S`, 탑승·하차가 동시라 합이 아닌 `maxf`,
  거리가 멀면 walk 항이 붙는다

**`test_boarding`** — `BoardingWatch` 판정:
- 반경 밖에서는 시작하지 않는다
- 반경 안이어도 속도가 `STOP_SPEED_MPS` 이상이면 시작하지 않는다
- 반경 안 + 정지면 시작한다
- 21 m 간격으로 겹친 정류장 두 곳에서 가까운 하나만 잡는다
- 반경을 통과만 하면 `stop_missed` 가 난다
- 타이머가 끝나면 `onboard` 가 대기 인원만큼 늘고 `boarding_finished` 가 난다

**`drive_smoke`** — 배선과 `StopField` 거리 컬링(전체 캡슐 수보다 갱신 수가
적어야 한다).

성능은 창 모드에서 따로 잰다. 기준은 기존과 같다 — 평균 60 fps, 최저 55 fps.

## 결정 기록

- **정차는 자동이다.** 문 여닫기 키를 따로 두지 않는다. 조작 부담만 늘고 저울질은
  안 늘어난다.
- **승객이 있는 정류장만 선다.** 114개를 전부 서면 승하차만 30분이다. 대기 인원이
  0인 정류장은 그냥 지나간다.
- **대기 인원은 보인다.** 멀리서 인원을 보고 "다음 신호 파랑일 때 밀어붙일까"를
  정하는 것이 저울질이다. 가까이서만 숫자가 보이면 판단이 늦어 의미가 없다.
- **승객마다 목적지를 준다.** 하차 인원을 따로 시드로 뽑는 것보다 코드가 거의 안
  늘면서, 탑승 인원이 노선 내내 오르내리는 것과 정원 초과가 공짜로 딸려 온다.
- **정차 위치 정확도는 걸어오는 시간으로 반영한다.** 차체 각도나 연석까지 거리는
  보지 않는다 — 추격 시점에서 연석 정렬을 눈으로 가늠하기 어려워 억울한 페널티가
  된다.
- **대기 인원은 매 플레이 새로 뽑는다.** 고정 시드면 두 번째 판부터 "이번 판은
  빠듯한가"라는 질문이 사라진다.
