# 교차로 모서리와 차량 모델 설계

작성일: 2026-09-27
범위: `road-fixes` 이후 플레이 피드백 3건과 인도 튀어나옴 스크린샷 2장. `road-fixes` 브랜치 위에서 한다.

## 배경

1. 사거리 한가운데나 모서리에 도로 면이 비어 바닥이 보인다.
2. 사거리 모서리에서 인도가 네모로 끊긴다. 도로를 따라 곡선으로 이어져야 한다.
3. 교통 차량이 색칠한 박스다. 받은 차량 모델
   (`~/Downloads/angular-apocalypse-abandoned-compact-car-intact-parked.glb`)을 쓴다.

조사 결과 원인:

1. `mesh.build_roads` 는 way 구간마다 사각형 리본을 깔고, way **중간** 꺾임점에만
   축 정렬 사각형 패치를 붙인다. 교차로는 대개 way 의 끝점이라 패치가 없다.
   두 갈래가 비스듬히 만나면 리본 모서리 사이에 쐐기꼴 틈이 남는다.
2. `mesh.build_sidewalks` 는 공유 노드(교차점)마다 앞뒤 `반폭 + 3 m` 를 잘라
   비운다. 모서리가 네모로 끊기고, 두 way 가 그냥 이어지는 노드(교차로가 아닌
   way 분할점)에서도 인도가 끊긴다.
3. 차량 모델: 메쉬 1개, 삼각형 5.8k, jpeg 텍스처 1장. 크기 1.6 x 0.78 x 0.9 m
   로 장난감 크기이고 긴 축이 X 다. 지금 차체 박스는 1.8 x 1.4 x 4.6 m 다.
4. 사용자 스크린샷 두 장(비스듬한 합류, 인도가 차도를 가로지름): 인도가 다른
   차도 위인지 **인도 중심선**만 2 m 간격으로 검사한다. 비스듬히 만나면 인도
   가장자리와 끝 모서리가 차도로 튀어나온다. 공유 노드가 없는 교차에서는 교차점
   자르기도 안 걸린다. 노드별 모깎기(이 문서 첫 판)로는 이 경우를 못 고쳐서
   면 연산 방식으로 바꿨다.

## 목표와 비목표

**목표**

- 도로 면에 틈이 없다. 교차점 모서리는 원호로 둥글다.
- 인도는 어떤 차도 면과도 겹치지 않는다(기하학적으로 보장).
- 인도가 도로를 따라 모서리를 곡선으로 돌아 이웃 도로 인도와 이어진다.
- 교통 차량이 받은 모델로 보이고, 차마다 색이 다르며 경찰차는 구별된다.

**비목표**

- 고가·지하차도 입체 처리. 지금처럼 평면에 겹쳐 합친다.
- 교차로 안 차선 도색 정리. 도색은 그대로다.
- 건물과 인도 겹침 처리.
- 차량 충돌면 변경. 박스 그대로 두고 겉모습만 바꾼다.
- 차종 여러 개. 모델 하나를 색만 바꿔 쓴다.

## 설계

### 1. 면 연산 (bake, 새 모듈 `tools/osmbake/surface.py`)

shapely 2.1 을 쓴다. bake 도구 전용이고 게임에는 필요 없다. Homebrew Python 은
전역 pip 설치를 막으므로 저장소 `.venv` 에 설치하고(`requirements.txt` 에
`shapely>=2.1`). `venv` 가 `.venv/.gitignore` 를 만들어 따로 무시할 필요가 없다. bake·파이썬 테스트·
`tests/bake/run_verify.sh` 는 `.venv/bin/python` 으로 돈다.

`build_surfaces(ways, projector) -> tuple[MeshBuilder, MeshBuilder]` (도로, 인도):

1. way 마다 중심선을 반폭만큼 `buffer`(끝 flat, 이음 round) 한 다각형.
   모두 합친 것이 `carriageway`.
2. 모서리 채우기: `carriageway.buffer(R).buffer(-R)`(닫힘 연산, R =
   `CORNER_RADIUS_M` 6 m)로 오목한 모서리를 반경 R 원호로 메운다. 평행한 옆
   도로끼리 붙지 않게, 채운 부분은 공유 노드 둘레 원(반경 = 그 노드에 닿는 도로
   중 최대 반폭 + 2R) 안만 쓴다. `road = carriageway ∪ (닫힘 ∩ 노드 원들)`.
3. 인도: 폭 `SIDEWALK_MIN_ROAD_WIDTH`(6 m) 이상 way 로만 만든 다각형 합을
   `CURB_SLOPE_M + SIDEWALK_WIDTH`(2.25 m) 넓힌 띠에서 `road` 를 뺀다.
   - 윗면(y `CURB_HEIGHT` 0.15) = 띠 - `road.buffer(CURB_SLOPE_M)`.
   - 연석 경사면 = 띠 ∩ (`road.buffer(CURB_SLOPE_M)` - `road`). 경사면 정점은
     모두 차도 경계(높이 0)나 윗면 경계(0.15) 위에 있으므로 차도에 닿는지만
     본다. 큰 다각형과 거리를 재는 것보다 훨씬 빠르다.
   - 띠에는 메운 모서리도 넣는다. 안 그러면 모서리 원호(모서리에서 2.49 m)가
     폭 2.25 m 띠를 먹어 모서리 인도가 끊긴다.
   - 원호 정점이 많아 모든 다각형을 0.05 m 로 단순화한다(삼각형 절반).
   - 골목(6 m 미만)은 인도가 없고, 골목이 끼어드는 자리에서 큰길 인도가 끊긴다.
4. 삼각분할: 다각형을 200 m 청크 격자 칸으로 잘라 `shapely.
   constrained_delaunay_triangles` 로 나눈다. 삼각형이 청크를 넘지 않는다.
   삼각형은 위를 향하게 감는다(외적 y 가 음수면 뒤집는다). 평면은 법선 UP,
   경사면은 삼각형마다 면 법선.
5. `cli.py` 는 `build_roads` / `build_sidewalks` 대신 이것을 부른다. 산출물
   표면 이름(`road`, `sidewalk`)은 그대로라 게임 쪽은 바뀌지 않는다.
6. `mesh.build_roads`, `build_sidewalks` 와 그것들만 쓰던 도우미·상수·테스트를
   지운다. `_road_index`, `_on_roadway` 는 `corridor.place_poles` 가 쓰므로 둔다.

시제품 측정(단순화 후): seoul-100 16.5 초, 도로 8.6 만 + 인도 20 만 삼각형
(기존 도로+인도 11.3 만). 654번 15.2 초, 서대문03 2.2 초. 기존 코리도 필터
70 초에 비하면 작다. 인도 삼각형 대부분은 폭 0.25 m 경사면 띠다.

### 2. 차량 모델 (게임)

- 모델을 `assets/models/car.glb` 로 복사하고 import 산출물을 같이 커밋한다.
- `traffic.gd` `_make_car` 가 `BoxMesh` 대신 이 씬을 인스턴스한다.
  - 크기는 축마다 `BODY_SIZE`(폭 1.8, 높이 1.4, 길이 4.6 m)에 맞춘다. 모델
    비율(길이/폭 1.77)이 뭉툭해서 길이에 맞춰 균일하게 키우면 폭 2.6 m, 높이
    2.2 m 가 되어 차선을 넘고 충돌 박스와 어긋난다. 길이 방향으로 1.44 배 더
    늘어나지만 각진 모델이라 어색하지 않다.
  - 긴 축이 X 이고 지붕이 +X 쪽으로 치우쳐 보닛(앞)이 -X 다. 차의 앞은 -Z 이므로
    Y 축으로 -90° 돌린다. 캡처로 확인한다.
  - 색은 텍스처 머티리얼을 복제해 `albedo_color` 에 기존 `BODY_COLORS` 를 곱한다.
    경찰차는 `POLICE_COLOR` 를 곱하고 경광등 박스를 지금처럼 올린다.
  - 복제 머티리얼은 색마다 하나를 만들어 공유한다.
- 충돌 박스는 그대로다.

## 테스트

- **파이썬 (`tests/osmbake/test_surface.py`, `.venv` 로 실행)**
  - 비스듬한(30°) T자 합류, 공유 노드 없이 교차하는 두 도로, 십자 교차로를
    합성한다.
    - 인도 삼각형 중심점이 어떤 way 의 차도 다각형(중심선 반폭 버퍼) 안에도 없다.
    - 인도 윗면 삼각형 정점 높이는 0.15, 도로 면은 0.
    - 모든 삼각형이 위를 향한다.
  - 십자 교차로(폭 20 m)에서 모서리 (10, 10) 안쪽 점과 바깥 대각선 1.4 m
    점(원호 안쪽)이 도로 면에 덮이고, 바깥 대각선 4.2 m 점은 인도다.
  - 일직선으로 이어진 두 way 의 인도는 공유 노드에서 끊기지 않는다(노드 옆
    인도 위 점이 인도 삼각형 안).
  - 평행한 두 도로(간격 30 m)는 합쳐지지 않는다(사이 점이 도로 면 밖).
  - 삼각형이 청크 경계를 넘지 않는다.
- **bake verify**: 세 노선 다시 굽고 `tests/bake/run_verify.sh` 통과. 지면
  커버리지가 지금(100번 99.8%, 654번 99.9%, 서대문03 99.9%) 아래로 떨어지지
  않는다. 정류장 인도 위 비율은 기준 0.65 이상.
- **게임**: 전체 게임 테스트 통과. `test_traffic` 에 차 몸체 아래 glb 인스턴스가
  있다는 단언을 더한다.
- **눈**: 교차로 6곳 위에서 캡처, 사용자 스크린샷과 같은 비스듬한 합류 한 곳,
  추격 시점 1장.

## 위험

- 닫힘 연산이 교차점 둘레의 가까운 두 도로 사이(12 m 미만)도 메운다. 분리
  차도의 좁은 중앙분리대가 교차점 근처에서 아스팔트로 덮일 수 있다. 실제로도
  교차로 안은 분리대가 끊기므로 둔다.
- 섬처럼 도로에 둘러싸인 작은 땅(교통섬)이 생긴다. 인도가 둘러싸면 그대로 둔다.
- 도로 메쉬를 통째로 새로 만들어 삼각형 수가 바뀐다. 성능 기준(평균 60 fps)은
  캡처 때 fps 로그로 본다.
- 버스가 모서리를 크게 돌면 연석 경사를 밟는다. 자율주행 검증 교착 거리가
  지금보다 짧아지면 R 을 늘린다.
- 차량 모델 텍스처가 "버려진 차" 느낌이다. 색을 곱해도 녹슨 질감이 남는다.
  보기 싫으면 텍스처를 빼고 단색으로 칠하는 쪽을 검토한다.
